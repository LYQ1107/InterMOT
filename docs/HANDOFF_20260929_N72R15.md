## 4. 4 个测试失败的复核

复现命令：

```bash
PYTHONPATH=. .venv/bin/python -m pytest -q
```

结果：`207 passed, 4 failed`（约 20.86 秒）。失败测试为：

1. `tests/test_n6_identity_namespace.py::test_single_person_wrong_id_correction_restores_public_id`
2. `tests/test_n6_identity_namespace.py::test_trackeval_synthetic_regression`
3. `tests/test_n7_baseline_preservation.py::test_n7_t12_correction_adds_no_idsw_to_others`
4. `tests/test_n8_temporal_observer.py::test_n8_t15_trackeval_idsw_drops_after_correction`

分层结论如下：

- 前三个测试 helper 直接把子进程命令写成字符串 `"python"`。上面的直接解释器命令没有把 `.venv/bin` 放进 `PATH`，所以先出现 `FileNotFoundError: [Errno 2] No such file or directory: 'python'`。这是测试启动环境/可移植性问题，不是 InterMOT 研究逻辑失败。
- 将 `.venv/bin` 放入 `PATH` 后重跑这四个测试，四个都能启动 TrackEval，但全部在固定 TrackEval checkout 的同一接口处失败：CLI 的通用 parser 对 `--SEQMAP_FILE` 使用 `nargs='+'`，得到单元素 list；`mot_challenge_2d_box.py` 随后把它传给 `os.path.isfile()`，产生 `TypeError: stat: path should be string, bytes, os.PathLike or integer, not list`。这是 pinned TrackEval 旧 CLI 与测试调用之间的第三方接口兼容问题。
- `tabulate` 已补入当前 `.venv`（`0.10.0`）；它不是这次复现的剩余根因。没有修改 TrackEval，也没有把这 4 个失败改写为通过。
- 其余测试在同一复现中通过；mock pipeline、SAM3 导入、CUDA/版本检查也通过。因此目前没有证据把这 4 个失败归因于 N72R15 研究代码。

## 8. 下一步最小验证实验

在获得并核验最小资产后，下一步不是训练或消融，而是一个单事件/单序列的
**provenance-complete appearance/candidate-quality diagnostic**：

1. 用一个冻结事件的真实输入和 MAIN_B0 candidate rows，确认 target 与每个 competitor 都有非空、有限、来源可追踪的 appearance embedding；记录 source、hash、availability 和 cosine。
2. 在 runtime sidecar 中确认不读取未来 GT，确认 candidate coverage、target-vs-competitor edge 分布和 assignment margin/decision boundary；GT 只在封存后作 post-hoc 标签。
3. 只有该小诊断显示 appearance 有方向性、候选覆盖足够且 provenance 完整，才考虑按原冻结协议重跑 N72R15 的 32-event formal replay；否则继续保留 `FAIL_FUTURE_EFFECT`，不放行 LoRA、selector、calibration 或下游训练。

本记录不授权改变 checkpoint、candidate definition、solver、评价门槛或交互协议。
